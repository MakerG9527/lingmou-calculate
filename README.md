# 灵眸智算 · 端侧神经符号计算器（可运行原型 v2）

本原型验证产品最核心、也最容易被质疑的一环：
**在完全本地、可断网的条件下，把一道题“理解 → 建模 → 求解 → 校验”地算出来——
而且“算”由确定性引擎完成、其结果可被独立回代验证。**

这与上一代“公式 OCR → 算式求值”的 demo 有本质区别：上一代遇中英文即乱码、
无法解方程组、也没有校验；本版把大模型放在**正确的位置**——只让它“翻译”，不让它“算账”。

## 技术链路

```
题面文本 ──▶ 建模器(大模型 / 规则) ──▶ 结构化 DSL ──▶ SymPy 精确求解 ──▶ 回代校验 ──▶ 结果(带 ✓)
            └ 只翻译、不计算 ┘                      └ 确定性、毫秒级 ┘   └ 可信护城河 ┘
```

- **建模端**：大模型把题面理解并翻译成一段结构化 DSL（JSON），**绝不输出答案**。
  断网或未配置时，自动回退到**纯本地规则建模器**，保证一定能跑。
- **求解端**：`SymPy` 确定性符号计算，给出精确解（如 `1/3`、`π/4`、`3x²`），毫秒级、无需联网。
- **校验端**：把解**回代**原问题独立验证（方程代回、积分求导还原、A·A⁻¹=I 等），
  每个结果都打 `✓ 回代通过` / `✗`。

> 这条“离线 + 理解建模 + 精确求解 + 回代校验”的闭环，正是区别于“大模型直接解题”的可信内核。

## 目录结构

```
lingmou/
  dsl.py           # DSL 定义与校验（建模器与求解器之间的契约/地基）
  solver.py        # 求解 dispatcher + 回代校验器（算账与可信的核心）
  modeler_rule.py  # 规则建模器（完全离线兜底）
  modeler_llm.py   # 大模型建模器（OpenAI 兼容接口，只产出 DSL）
  pipeline.py      # 编排：建模 → 求解 → 校验，含自动回退
app.py             # Gradio 界面，显式展示 DSL、精确解与校验徽章
```

## 支持题型

解方程 / 方程组、求导、（定/不定）积分、矩阵（行列式/逆/秩/转置/特征值/加乘）、
单表达式精确求值，以及常见**应用题文字建模**（先抽象成方程组，再交求解）。

## 运行

```bash
pip install -r requirements.txt

# 配置大模型（OpenAI 兼容；不配也能跑——自动用规则建模兜底）
export LINGMOU_API_BASE=https://your-endpoint/v1
export LINGMOU_API_KEY=sk-xxx
export LINGMOU_MODEL=qwen2.5-7b-instruct   # 你的模型名

python app.py     # 浏览器打开终端显示的本地地址
```

界面里可切换“**自动 / 仅大模型 / 仅规则**”三种建模方式，方便现场对比演示。

### 关于“先 API、后本地”

`modeler_llm.py` 用的是 **OpenAI 兼容接口**。现在指向你的云端 API 跑通；
未来换本地推理（如 `llama.cpp` / `vLLM` 的 OpenAI 兼容 server），
只需把 `LINGMOU_API_BASE` 指向本地地址，**这段代码一行都不用改**。
接口不变、部署可换——这就是该路线的关键。

### 断网演示建议

- 选“仅规则（完全离线）”，可当场拔网演示完整链路；
- 或把本地推理 server 跑起来、`LINGMOU_API_BASE` 指向 `http://127.0.0.1:...`，同样断网可跑。

## 与申报书的对应

| 申报书 | 本原型对应 |
|---|---|
| 支柱一·精确计算内核（成熟库，确定性） | `solver.py`：SymPy 精确求解 |
| 支柱二·理解建模 + 主动核对 | `modeler_*.py` 产出 DSL + 界面可见的 DSL/校验 |
| 支柱三·全程离线 | 规则兜底 + 本地推理，可断网 |
| 受控建模（不做不可验证的开放建模） | DSL 是封闭集合，每个 task 都可回代校验 |
